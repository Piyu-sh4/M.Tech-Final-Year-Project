# 🧠 UX Design — Workforce Intelligence

## UX Principles

1. **Zero learning curve** — HR workflows match mental models from paper processes
2. **One click to value** — Key actions reachable in ≤ 2 clicks from dashboard
3. **Instant feedback** — Every action gets a toast, no silent operations
4. **Safe defaults** — Dangerous actions (payroll lock, delete) require confirmation
5. **Graceful degradation** — AI unavailable? Core HR still works perfectly

## 1. User Journey: HR Manager (Monthly Payroll)

```
8:00 AM — Open WFI
    │
    ▼
Admin Dashboard
    ├── KPI: "September payroll — NOT RUN ⚠️"
    ├── Quick action: "Run September Payroll →"
    │
    ▼
salary.html
    ├── Month auto-filled (Sep 2026)
    ├── Employee count: 47
    ├── Estimated total: ₹47,23,400
    │
    ▼ [Run Payroll]
    ├── Loading indicator (18s)
    ├── Toast: "✅ Payroll processed for 47 employees"
    │
    ▼
    ├── KPIs update in real-time
    ├── "Print Report" → formatted ₹ report opens
    ├── "Export CSV" → downloads instantly
    │
    ▼
    ├── Navigate to Payslip Portal
    ├── "Email All Payslips" → sends to 47 employees
    │
    ▼
    ├── Navigate to Compliance Dashboard
    ├── PF challan auto-calculated ✅
    ├── ESI challan auto-calculated ✅
    └── TDS: "24Q due in 8 days" — reminder shown
```

**UX Wins**:
- Payroll month auto-detected (current month, first 5 days = previous)
- Estimated total shown before running (confidence check)
- Progress indicator with time estimate
- One-click PDF + CSV after run
- Compliance reminders surfaced proactively

## 2. User Journey: Employee (Apply for Leave)

```
Employee Dashboard
    ├── Widget: "Leave Balance: 12 days ✅"
    ├── Quick action: "Apply Leave →"
    │
    ▼
leave.html

    ├── "Days requested: 3 | Balance after: 9"

    │
    ▼ [Submit]
```

**UX Wins**:
- Zero data entry — name/dept pre-filled from profile

- Real-time balance calculation as dates selected

## 3. Interaction Patterns

### 3.1 Tab Navigation
- Active tab: blue border + background tint
- Content switches instantly (no page reload)
- First tab always active on page load
- Tab state NOT preserved on refresh (intentional — always fresh data)

```js
// Pattern used across all tabbed pages
window.showTab('overview', buttonElement)
// Hides all panels matching id="tab*" or id="section-*"
// Shows panel matching id="tab{Name}"
// Updates active class on button
```

### 3.2 Forms
- Labels always above inputs (never placeholder-only)
- Real-time validation (red border + helper text on blur)
- Submit button disabled during API call (prevents double-submit)
- Success: toast + form reset or redirect
- Error: toast + focus back to first error field

### 3.3 Confirmation Dialogs
Used for destructive/irreversible actions:
```
[Lock Payroll] → "Are you sure? This cannot be undone for Sep 2026." → [Confirm] / [Cancel]
[Delete Employee] → "Type employee name to confirm deletion" → [Confirm]
[Revert Payroll] → "This will delete all Sep 2026 payslips." → [Confirm]
```

### 3.4 Loading States
```html
<!-- Skeleton loader for cards -->
<div class="skeleton" style="height:80px;border-radius:12px;
  background:linear-gradient(90deg,#f1f5f9 25%,#e2e8f0 50%,#f1f5f9 75%);
  background-size:200% 100%;animation:shimmer 1.5s infinite">
</div>

<!-- Button loading state -->
<button onclick="submitPayroll(this)">
  // onclick: this.disabled=true; this.textContent='Processing...'
  // on complete: this.disabled=false; this.textContent='Run Payroll'
</button>
```

### 3.5 Empty States
Every table/list shows a meaningful empty state:
```html
<div class="empty-state">
  <div style="font-size:2.5rem">📭</div>
  <div style="font-weight:700;margin:8px 0">No leave requests found</div>
  <div style="color:#64748b;font-size:.8rem">Apply for leave using the button above</div>
  <button class="btn-primary" onclick="...">Apply Leave</button>
</div>
```

### 3.6 Error States
```html
<!-- API error state -->
<div style="background:#FEF2F2;border:1px solid #FECACA;border-radius:10px;padding:16px">
  <div style="color:#DC2626;font-weight:700">⚠️ Failed to load payroll data</div>
  <div style="color:#64748b;font-size:.78rem;margin-top:4px">Check your connection and try again</div>
  <button onclick="loadPayrollData()" style="margin-top:10px;...">Retry</button>
</div>
```

## 4. Micro-interactions

### Toast Notifications (window.st)
```
Success: Green gradient, ✅ icon, 3 second auto-dismiss, slides up from bottom-right
Error:   Red gradient, ⚠️ icon, 5 second (longer — needs attention), slides up from bottom-right
Info:    Blue gradient, ℹ️ icon, 3 second auto-dismiss
```

### Dark Mode Toggle
```
Click → body.dark-mode toggles
Icon: 🌙 (light mode) → ☀️ (dark mode)
Transition: 0.3s on all colour properties
Saved: localStorage.wfi_dark_mode = '1' or '0'
```

### Card Hover
```
translateY(-4px) + box-shadow 0 8px 30px rgba(0,0,0,0.08)
Duration: 0.2s ease
Cursor: pointer (clickable cards)
```

### Button States
```
Default:  Full opacity
Hover:    0.88 opacity + slightly lighter
Active:   0.75 opacity (pressed feel)
Disabled: 0.5 opacity + cursor: not-allowed
Loading:  0.7 opacity + spinner icon
```

## 5. Accessibility

### Current Implementation
- All form inputs have associated `<label>` elements
- Buttons have descriptive text (not just icons)
- Color is never the only indicator (badges always have text too)
- Focus styles visible (`outline: 3px solid var(--accent)` on focus)
- Touch targets minimum 44×44px on mobile

### Keyboard Navigation
- Tab order follows visual layout
- Enter/Space activate buttons
- Escape closes modals and lightbox
- Arrow keys navigate tab bars

### Screen Reader Considerations
- `alt` attributes on all images
- `aria-label` on icon-only buttons
- `role="alert"` on toast notifications
- `aria-expanded` on accordion/sidebar groups

## 6. UX Patterns by Page Type

### Dashboard Pages
- KPI tiles at top (scannable at a glance)
- Activity feed on right (recent actions)
- Charts in middle (trend context)
- Quick actions floating or in header

### List/Table Pages
- Search + filter bar at top
- Export (Print/CSV) in header bar
- Pagination at bottom
- Row actions on hover (Edit/View/Delete)
- Bulk select checkbox column

### Form Pages
- Single column on mobile, two column on desktop
- Progress indicator for multi-step forms
- Save Draft + Submit (primary) buttons
- Cancel link (not button — less prominent)

### Report Pages
- Export bar always visible (Print + CSV)
- Summary KPIs above the table
- Table with sticky header on scroll
- Print preview matches `@media print` styles
